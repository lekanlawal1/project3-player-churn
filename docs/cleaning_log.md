## Clean

- **Dropped surrogate index and URL columns (Photo, Flag, Club Logo)** — presentation assets, not signal; keeping them invites accidental joins on junk.
- **Dropped 26 per-position rating columns (CAM, ST, …)** — they are formula-derived from the 34 base skills (values like '88+2'), so they add collinearity, parsing pain, and zero new information.
- **Removed 52 duplicate/invalid player IDs (kept highest Overall)** — the scrape occasionally lists a player twice mid-update; the higher-rated row is the later snapshot. Duplicate IDs would double-count players and corrupt the join to FIFA 19.
- **Parsed Value/Wage strings ('€110.5M', '€565K') into numeric EUR; 0 unparseable → NULL** — money arrives as display text; models need numbers. NULLs are kept (not zeroed) so missing wages can't masquerade as free transfers.
- **Derived primary_position (first listed preferred position)** — 'ST LW' collapses to 'ST'; one categorical with 15 levels beats a ragged multi-label string for both SQL bucketing and modeling.
- **Coerced Age/Overall/Potential and 34 skill ratings to numeric; snake_cased all names** — GK rows legitimately lack some outfield ratings (kept as NULL, imputed at model time, not silently zero-filled — a 0 rating means 'terrible', not 'not applicable').
- **Kept 248 club-less FIFA 18 rows in the clean layer but excluded them from modeling scope** — free agents have no club to churn *from*; the question is 'will we lose this squad member', which is undefined without a squad.
- **Reduced FIFA 19 to (id, club) only** — the next-season club is the label source; every other FIFA 19 column is future information a squad planner wouldn't have, i.e. leakage.
- **Wrote clean_f18 (17,929 rows) and clean_f19_clubs (18,207 rows) to DuckDB** — the clean layer is the contract the SQL stage builds on.
